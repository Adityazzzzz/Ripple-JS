Ripple's API was designed to feel familiar to developers coming from other ecosystems.

## From Vue Reactivity

Vue's Composition API is heavily based on reactivity. Ripple operates very similarly.

| Vue | Ripple |
| --- | --- |
| `ref(0)` | `signal(0)` |
| `computed(() => ...)` | `computed(() => ...)` |
| `watchEffect(() => ...)` | `effect(() => ...)` |
| `watch(source, () => ...)` | `watch(source, () => ...)` |
| `reactive({ ... })` | N/A (Use `createStore` or individual signals) |

**Key Differences:**
- Vue's `ref` uses `.value`, Ripple's `signal` also uses `.value`.
- Vue auto-unwraps refs in templates; Ripple requires `.value` unless using framework adapters.

## From Preact Signals

Ripple is practically a drop-in replacement for Preact Signals in core logic.

| Preact Signals | Ripple |
| --- | --- |
| `signal(0)` | `signal(0)` |
| `computed(() => ...)` | `computed(() => ...)` |
| `effect(() => ...)` | `effect(() => ...)` |
| `batch(() => ...)` | `batch(() => ...)` |
| `signal.peek()` | `signal.peek()` |

## From SolidJS

Solid uses getter/setter tuples instead of object properties. Ripple supports this via `signal.tuple`.

<Tabs>
  <TabItem label="SolidJS">
    ```ts
    const [count, setCount] = createSignal(0);
    const double = createMemo(() => count() * 2);
    
    createEffect(() => console.log(double()));
    setCount(1);
    ```
  </TabItem>
  <TabItem label="Ripple">
    ```ts
    const [count, setCount] = signal.tuple(0);
    const double = computed(() => count() * 2);
    
    effect(() => console.log(double.value));
    setCount(1);
    ```
  </TabItem>
</Tabs>
